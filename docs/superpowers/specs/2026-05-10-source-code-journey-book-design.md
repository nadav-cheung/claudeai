# 《跟着消息走：Claude Code 源码的旅程》 书籍设计

> 四卷本源码分析书，以《网络是怎么连接的》叙事风格，跟随一条消息穿越 Claude Code 系统。
> 读者从编程新手成长为项目 Contributor。

---

## 1. 书籍概述

| 项目 | 内容 |
|------|------|
| 书名 | 跟着消息走：Claude Code 源码的旅程 |
| 目标源码 | Claude Code CLI（当前仓库 src/ 目录） |
| 写作语言 | 中文，代码和术语保留英文 |
| 目标读者 | 编程新手（会写代码但没看过大型项目源码） |
| 风格 | 《网络是怎么连接的》纯叙事旅程风格 |
| 篇幅 | 四卷 48 章，每章 3000-5000 字，总计约 15-24 万字 |
| 与现有内容关系 | 完全从零重写，不参考现有 21 章内容 |
| 文件位置 | `teaching/v2/` 目录下 |

### 1.1 独特价值

1. **叙事驱动** — 不是按模块组织的技术手册，而是跟随消息穿越系统的旅程
2. **概念自然引入** — TypeScript 概念在需要时才出现，不前置堆砌
3. **场景化标题** — 每章标题是一个具体场景，不是抽象概念
4. **四阶段成长** — 卷一追踪者→卷二理解者→卷三创造者→卷四架构师
5. **编程新手友好** — 从"什么是源码"开始，不假设先验知识

### 1.2 写作原则

- **第二人称叙事**：用"你"和"你的消息"
- **场景钩子**：每章开头一句话交代消息当前在哪
- **生活类比**：消息像快递、工具像工具箱、权限像门卫
- **代码片段**：展示真实源码的关键部分，附带中文注释
- **下一站预告**：每章结尾预告消息即将进入的下一站
- **不用列表式教学**：避免"1.2.3 步骤"的教科书口吻

### 2.1 卷与能力映射

| 卷 | 书名 | 叙事视角 | 读完能力 |
|---|------|---------|---------|

| 卷四 | 架构师的棋盘 | 退后一步看全局，看「为什么这样设计」 | 参与架构讨论、理解设计权衡 |

## 3. 卷一：消息的旅程（12 章）

> **叙事线**：你安装了 Claude Code，输入"帮我修个 bug"，跟着这条消息穿越整个系统。

| 3 | 消息被装进信封 | 用户输入变成 API 消息 | 类型、接口、JSON | `src/services/api/claude.ts` |

| 7 | 命令真的被执行了 | BashTool 子进程 | child_process、Buffer | `src/tools/BashTool/` |

| 11 | 屏幕上的每一帧 | Ink/React 终端渲染 | JSX、组件、props | `src/ink/`, `src/components/` |
| 12 | 你的第一次追踪 | 实战：跟着真实请求走一遍 | 断点、console.log | 全流程 |

## 8. 质量标准

### 8.1 源码准确性

- 所有代码片段引用真实源码文件和行号
- 函数名、类名、变量名必须与源码一致
- 代码片段保留原始英文注释，添加中文翻译

### 8.2 叙事质量

- 每章有明确的场景钩子和下一站预告
- 概念引入自然，不前置堆砌
- 生活类比恰当，不牵强附会
- 全书保持第二人称视角

### 8.3 新手友好

- 不假设读者了解 TypeScript
- 不假设读者了解 React
- 不假设读者了解 CLI 工具开发
- 不假设读者了解 API 通信

### 8.4 成长验证

每卷结尾的章节（卷一第12章、卷二第12章、卷三第12章）都是实战章节，读者通过完成这些章节验证自己达到了该卷的能力目标。

## 9. 实施策略

### 9.1 写作顺序

按卷顺序写，每卷内按章顺序写。原因：
- 叙事线是连续的，后面的章节依赖前面的设定
- TypeScript 概念逐步引入，不能跳步

### 9.2 每章写作流程

1. 确定本章的源码范围（哪些文件、哪些函数）
2. 阅读和理解源码
3. 确定要引入的 TS 概念
4. 写叙事段落
5. 插入代码片段和注释
6. 写下一站预告
7. 审校：确认源码引用准确

### 9.3 预计产出

- 每章 3000-5000 字
- 每卷 12 章
- 四卷共 48 章
- 总计约 15-24 万字
