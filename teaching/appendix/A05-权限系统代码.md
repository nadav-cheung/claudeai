## 1. 权限检查入口：hasPermissionsToUseTool()

**文件**：`src/utils/permissions/permissions.ts:100-200`

**功能**：核心权限检查函数，合并规则、分类器、沙箱等多个信号。

```typescript
// src/utils/permissions/permissions.ts:100
export async function hasPermissionsToUseTool(
  tool: Tool,
  input: unknown,
  context: ToolUseContext,
): Promise<PermissionResult> {

  // 1. 规则匹配检查
  const ruleResult = checkRuleBasedPermissions(tool, input, context)
  if (ruleResult.behavior !== 'ask') {
    return ruleResult
  }

  // 2. Bash 分类器检查（如果启用）
  if (tool.name === BASH_TOOL_NAME && isBashClassifierEnabled()) {
    const classifierResult = await runBashClassifier(input, context)
    if (classifierResult.confidence === 'high') {
      return {
        behavior: classifierResult.matches ? 'allow' : 'deny',
        decisionReason: {
          type: 'classifier',
          classifier: 'bash_allow' as const,
          confidence: classifierResult.confidence,
        }
      }
    }
  }

  // 3. Auto 模式分类器检查
  if (isAutoModeActive() && isTranscriptClassifierEnabled()) {
    const transcriptResult = await runTranscriptClassifier(tool, input, context)
    if (transcriptResult.confidence === 'high') {
      return {
        behavior: transcriptResult.matches ? 'allow' : 'deny',
        decisionReason: { type: 'classifier', classifier: 'auto-mode', ... }
      }
    }
  }

  // 4. 沙箱自动放行
  if (isRunningInSandbox() && context.autoAllowBashIfSandboxed) {
    return { behavior: 'allow', decisionReason: { type: 'sandboxOverride' } }
  }

  // 5. 默认：需要交互确认
  return { behavior: 'ask' }
}
```

### 1.1 权限决策流程图

```
工具调用请求
     │
     ▼
checkRuleBasedPermissions()
     │
     ├── deny 规则匹配 → return deny
     ├── allow 规则匹配 → return allow
     └── 无匹配 → continue
     │
     ▼
Bash Classifier (if Bash + enabled)
     │
     ├── 高置信度 allow → return allow
     ├── 高置信度 deny → return deny
     └── 低置信度 → continue
     │
     ▼
Auto Mode Classifier (if active)
     │
     ├── 高置信度 → return allow/deny
     └── 低置信度 → continue
     │
     ▼
Sandbox Override (if in sandbox + autoAllow)
     │
     └── return allow
     │
     ▼
return ask (需要用户确认)
```

## 2. 规则匹配：checkRuleBasedPermissions()

**文件**：`src/utils/permissions/permissions.ts:50-90`

**功能**：检查用户配置的 allow/deny 规则。

```typescript
// src/utils/permissions/permissions.ts:50
export function checkRuleBasedPermissions(
  tool: Tool,
  input: unknown,
  context: ToolUseContext,
): PermissionResult {
  const permissionContext = context.options.permissionContext

  // 按优先级遍历所有规则源
  for (const ruleSource of RULE_SOURCES) {
    const rules = permissionContext.rules[ruleSource]

    for (const rule of rules) {
      // 检查规则是否匹配当前工具和输入
      const matchResult = matchRule(rule, tool, input)

      if (matchResult.matches) {
        // deny 规则优先
        if (rule.behavior === 'deny') {
          return {
            behavior: 'deny',
            decisionReason: {
              type: 'rule',
              rule: {
                source: ruleSource,
                pattern: rule.pattern,
              }
            }
          }
        }

        if (rule.behavior === 'allow') {
          return {
            behavior: 'allow',
            decisionReason: {
              type: 'rule',
              rule: {
                source: ruleSource,
                pattern: rule.pattern,
              }
            }
          }
        }
      }
    }
  }

  // 无匹配规则
  return { behavior: 'ask' }
}
```

### 2.1 规则源优先级

```typescript
// src/utils/permissions/permissions.ts:30
const RULE_SOURCES = [
  'cliArg',          // 命令行参数（最高）
  'flagSettings',    // 标志设置
  'policySettings',   // 策略设置（管理员）
  'projectSettings',  // 项目级 .claude/settings.json
  'userSettings',    // 用户级 ~/.claude/settings.json
  'localSettings',   // 本地 settings.local.json
  'session',        // 会话临时规则（最低）
]
```

**关键设计**：deny 规则优先于 allow 规则，高优先级源覆盖低优先级源。

## 3. Bash 分类器：classifyBashCommand()

**文件**：`src/utils/permissions/bashClassifier.ts:50-120`

**功能**：使用 AI 模型判断 Bash 命令的安全性。

```typescript
// src/utils/permissions/bashClassifier.ts:50
export async function classifyBashCommand(
  command: string,
  cwd: string,
  descriptions: string[],  // 规则描述，如 "prompt: running npm test"
  behavior: 'deny' | 'ask',
  signal: AbortSignal,
  isNonInteractiveSession: boolean,
): Promise<ClassifierResult> {

  // 构建分类 prompt
  const prompt = buildClassifierPrompt(command, cwd, descriptions)

  // 调用 AI 模型
  const response = await callClassifierModel({
    prompt,
    signal,
    // 非交互式会话使用更严格的分类
    temperature: isNonInteractiveSession ? 0.1 : 0.3,
  })

  // 解析响应
  return parseClassifierResponse(response, behavior)
}

// 构建分类 prompt
function buildClassifierPrompt(
  command: string,
  cwd: string,
  descriptions: string[]
): string {
  return `You are a security classifier for bash commands.

Current directory: ${cwd}
Command to classify: ${command}

Allowed command patterns (from user rules):
${descriptions.map(d => `- ${d}`).join('\n')}

Classify this command as:
- MATCH: The command matches an allowed pattern
- DENY: The command is clearly dangerous and should be denied
- ASK: The command doesn't clearly match or deny

Respond with only: MATCH, DENY, or ASK`
}
```

## 4. 拒绝追踪：denialTracking

**文件**：`src/utils/permissions/denialTracking.ts:30-80`

**功能**：追踪分类器的拒绝次数，防止无限拒绝。

```typescript
// src/utils/permissions/denialTracking.ts:30
export const DENIAL_LIMITS = {
  maxConsecutive: 3,   // 连续拒绝 3 次
  maxTotal: 20,        // 总共拒绝 20 次
}

export function shouldFallbackToPrompting(
  state: DenialTrackingState
): boolean {
  return (
    state.consecutiveDenials >= DENIAL_LIMITS.maxConsecutive ||
    state.totalDenials >= DENIAL_LIMITS.maxTotal
  )
}

// 更新追踪状态
export function updateDenialState(
  currentState: DenialTrackingState,
  decision: PermissionDecision
): DenialTrackingState {
  if (decision.behavior === 'deny') {
    return {
      consecutiveDenials: currentState.consecutiveDenials + 1,
      totalDenials: currentState.totalDenials + 1,
    }
  }

  // 非 deny 决策，重置连续计数
  return {
    ...currentState,
    consecutiveDenials: 0,
  }
}
```

**设计意图**：
- 连续拒绝 3 次后，回退到提示模式
- 防止分类器在不确定情况下"卡住"
- 平衡安全性和可用性

## 5. 权限上下文创建

**文件**：`src/hooks/toolPermission/PermissionContext.ts:30-80`

**功能**：创建权限检查所需的上下文对象。

```typescript
// src/hooks/toolPermission/PermissionContext.ts:30
export function createPermissionContext(
  toolName: string,
  input: unknown,
  context: ToolUseContext,
): PermissionContext {
  return {
    toolName,
    input,
    toolUseContext: context,

    // 构建权限决策结果
    buildAllow: (input, decisionReason) => ({
      behavior: 'allow' as const,
      updatedInput: input,
      decisionReason,
    }),

    buildDeny: (message, decisionReason) => ({
      behavior: 'deny' as const,
      message,
      decisionReason,
    }),

    buildAsk: (updatedInput) => ({
      behavior: 'ask' as const,
      updatedInput,
    }),

    // 检查是否已中止
    resolveIfAborted: () => {
      if (context.abortController.signal.aborted) {
        throw new ToolUseAbortedError()
      }
    },

    // 记录决策日志
    logDecision: (decision: PermissionDecision) => {
      logEvent('tengu_permission_decision', {
        toolName,
        behavior: decision.behavior,
        reason: decision.decisionReason,
        sessionId: context.sessionId,
      })
    },
  }
}
```

## 练习

### 练习 1：分析权限检查流程

**问题**：当用户执行 `rm -rf /tmp/test` 时，权限检查的完整流程是什么？

**答案**：

```
rm -rf /tmp/test
    ↓
classifyBashCommand() [bashClassifier.ts]
    ↓ 识别为 destructive + dangerous
hasPermissionsToUseTool()
    ↓
checkRuleBasedPermissions() [permissions.ts]
    ↓
matchRule("rm *") → 匹配到 "disallow rm *"
    ↓
返回 { behavior: 'deny', reason: 'Rule matched: disallow' }
    ↓
用户看到权限拒绝对话框
```

**Java 对比**：类似于 Spring Security 的 `AccessDecisionManager` 投票机制。

---

### 练习 2：规则匹配算法

**问题**：规则 `allow Read ** /*.ts` 和 `allow Write ** /*.md` 分别匹配什么？

**答案**：

| 规则 | 匹配示例 | 不匹配示例 |
|------|---------|-----------|
| `allow Read ** /*.ts` | `Read /src/main.ts` | `Read /src/main.js` |
| `allow Write ** /*.md` | `Write /docs/README.md` | `Write /docs/README.txt` |

**匹配逻辑**：
- 第一段：`Read` / `Write` — 工具名称
- 第二段：`**` — 任意路径
- 第三段：`/*.ts` / `/*.md` — 文件扩展名过滤

### 练习 3：拒绝追踪机制

**问题**：为什么需要追踪连续拒绝次数？何时会触发回退到提示模式？

**答案**：

```typescript
const DENIAL_LIMITS = {
  maxConsecutive: 3,  // 连续 3 次拒绝
  maxTotal: 10,       // 总计 10 次拒绝
}

shouldFallbackToPrompting(state) {
  return (
    state.consecutiveDenials >= 3 ||  // 或
    state.totalDenials >= 10            // 总计超过限制
```

**设计原因**：
- 防止分类器在不确定情况下"卡住"
- 连续拒绝说明分类器可能对这类命令判断不准
- 回退到提示模式让用户明确决定

### 练习 5：Bash 命令分类

**问题**：`classifyBashCommand()` 如何判断一个命令是 destructive 的？

**答案**：

**危险信号检测**：
```typescript
// 危险模式
const DANGEROUS_PATTERNS = [
  /rm\s+.*-rf/,           // rm -rf
  /dd\s+.*of=/,           // dd of=
  /mkfs/,                  // 格式化
  /:(){ :|:& };:/,       // Fork bomb
]

// 检查匹配
for (const pattern of DANGEROUS_PATTERNS) {
  if (pattern.test(command)) {
    return { isDangerous: true, isDestructive: true }
  }
}
```

**分类结果**：
```typescript
interface BashClassification {
  isDangerous: boolean      // 是否危险
  isDestructive: boolean    // 是否破坏性
  isNetwork: boolean       // 是否有网络操作
  isReadOnly: boolean      // 是否只读
}
```
