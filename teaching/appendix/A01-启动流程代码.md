## 1. CLI 入口：main()

**文件**：`src/main.tsx:585-700`

**功能**：CLI 主入口函数，协调整个启动流程。

```typescript
// src/main.tsx:585
export async function main() {
  // 1. 安全：防止 Windows PATH 劫持
  process.env.NoDefaultCurrentDirectoryInExePath = '1'

  // 2. 初始化警告处理
  initializeWarningHandler()

  // 3. 注册退出时的光标恢复
  process.on('exit', () => resetCursor())

  // 4. 处理 SIGINT（Ctrl+C）
  process.on('SIGINT', () => {
    // 非 print 模式下，SIGINT 正常退出
    if (!process.argv.includes('-p') && !process.argv.includes('--print')) {
      process.exit(0)
    }
  })

  // 5. 早期参数处理
  eagerLoadSettings()
  initializeEntrypoint(isNonInteractive)

  // 6. 处理 cc:// URL（Direct Connect）
  if (process.argv.some(arg => arg.startsWith('cc://'))) {
    await handleDirectConnect(process.argv)
    return
  }

  // 7. 构建 Commander.js 命令
  const program = buildCLIProgram()

  // 8. 执行命令
  await program.parseAsync(process.argv)
}
```

### 2.1 API 预连接

```typescript
// src/entrypoints/init.ts:150
async function preconnectAnthropicApi(): Promise<void> {
  const apiUrl = getAnthropicApiUrl()

  // 建立 TCP 连接
  const socket = await createConnection({
    host: apiUrl.hostname,
    port: apiUrl.port || 443,
  })

  // 预热 TLS（如果是 HTTPS）
  if (apiUrl.protocol === 'https:') {
    await tls handshake(socket, apiUrl.hostname)
  }

  // 保持连接活跃
  socket.setKeepAlive(true)

  // 存储以供后续使用
  globalApiSocket = socket
}
```

## 3. REPL 启动：launchRepl()

**文件**：`src/replLauncher.tsx:50-100`

**功能**：启动交互式 REPL 界面。

```typescript
// src/replLauncher.tsx:50
export async function launchRepl(
  root: Root,
  appProps: AppProps,
  replProps: REPLProps,
  renderAndRun: RenderFunction
): Promise<void> {
  // 1. 动态导入 React 组件
  const { App } = await import('./components/App.js')
  const { REPL } = await import('./screens/REPL.js')

  // 2. 构建 App props
  const stats = createStatsStore()
  const initialState = await buildInitialAppState()

  // 3. 构建 React 组件树
  const appElement = (
    <App
      stats={stats}
      initialState={initialState}
      getFpsMetrics={createFpsMetrics}
    >
      <FpsMetricsProvider getFpsMetrics={createFpsMetrics}>
        <StatsProvider store={stats}>
          <AppStateProvider initialState={initialState}>
            <MailboxProvider>
              <VoiceProvider>
                <REPL {...replProps} />
              </VoiceProvider>
            </MailboxProvider>
          </AppStateProvider>
        </StatsProvider>
      </FpsMetricsProvider>
    </App>
  )

  // 4. 渲染并运行
  await renderAndRun(root, appElement)
}
```

## 练习

### 练习 1：追踪启动阶段

**问题**：Claude Code 的启动分为哪 5 个阶段？每个阶段的主要工作是什么？

**答案**：

| 阶段 | 名称 | 主要工作 | 耗时 |
|------|------|---------|------|
| Phase 0 | 模块加载 | import 阶段，并行执行 MDM/Keychain 预取 | ~135ms |
| Phase 1 | 安全预检 | CLI 参数解析、early 处理 | ~5ms |
| Phase 2 | 初始化 | init() 执行所有初始化逻辑 | ~100ms |
| Phase 3 | 认证配置 | API Key/OAuth 检查、GrowthBook 初始化 | ~50ms |
| Phase 4 | REPL 渲染 | React 组件树渲染 | ~50ms |

**Java 对比**：类似于 Spring Boot 的 `ApplicationRunner` 执行顺序。

---

### 练习 2：理解 API 预连接

**问题**：为什么 `preconnectAnthropicApi()` 能提升性能？它实际上建立了什么连接？

**答案**：

```typescript
// 预连接建立 TCP + TLS
const socket = await createConnection({
  host: apiUrl.hostname,
  port: 443,
})
await tls.handshake(socket, apiUrl.hostname)  // TLS 握手
socket.setKeepAlive(true)
```

**性能提升原理**：
- TCP 连接建立：~50-100ms
- TLS 握手：~100-150ms
- **总计**：~150-250ms 被提前到 init 阶段

用户输入第一个问题前，连接已经准备好，首次 API 响应更快。

**Java 对比**：类似于 HikariCP 连接池预热。

---

### 练习 3：分析 Provider 层级

**问题**：React Provider 层级 `App → FpsMetricsProvider → StatsProvider → AppStateProvider → MailboxProvider → VoiceProvider → REPL` 的设计意图是什么？

**答案**：

1. **隔离关注点**：每个 Provider 独立管理一个功能域
2. **按需渲染**：只有 REPL 组件依赖的 context 变化时才重渲染
3. **可测试性**：可以单独测试每个 Provider 的逻辑

```
FpsMetricsProvider  → FPS 监控（高频更新）
StatsProvider      → 统计数据
AppStateProvider   → 应用状态
MailboxProvider    → Agent 间通信（跨进程）
VoiceProvider      → 语音模式
REPL              → 主交互屏幕
```

**Java 对比**：类似于 Spring 的多层 Bean 容器，每个容器管理特定类型的服务。

---

### 练习 4：后台预取的作用

**问题**：`startDeferredPrefetches()` 为什么要设计为"非阻塞"？哪些操作被预取？

**答案**：

**设计原因**：
- 用户首次看到 REPL 界面后，需要"准备输入"的时间（~500ms）
- 这段时间内 CPU 空闲，可以并行执行预取操作

**预取内容**：
```typescript
initUser()                    // 用户信息（~100ms）
getUserContext()              // 用户上下文（~50ms）
getSystemContext()            // git status 等（~200ms）
getRelevantTips()              // 提示信息（~50ms）
countFilesRoundedRg()         // 文件计数（~100ms）
initializeAnalyticsGates()     // 分析初始化（~50ms）
```

**总计**：~550ms 的 I/O 操作隐藏在用户准备输入的时间里。

**Java 对比**：类似于 `@Async` 注解的异步初始化。

---

### 练习 5：懒加载模式

**问题**：为什么 Claude Code 使用 `require()` 懒加载而不是直接 import？

**答案**：

**问题**：直接 import 会触发模块初始化，可能：
1. 触发循环依赖
2. 增加启动时间
3. 加载不必要的代码

**解决方案**：函数包装的 require
```typescript
const getTool = () => require('./tools/Tool.js').Tool

// 调用时才加载
const Tool = getTool()
```

**另一个场景**：Feature Flag
```typescript
const coordinatorModule = feature('COORDINATOR_MODE')
  ? require('./coordinator/coordinatorMode.js')
  : null
```
编译时静态分析，未使用的模块不会被打包。

**Java 对比**：类似于 Spring 的 `@Lazy` 注解，延迟 Bean 初始化。
