## 1. 压缩主函数：compactConversation()

**文件**：`src/services/compact/compact.ts:100-200`

**功能**：执行完整的对话压缩，生成摘要并重建消息列表。

### 1.1 函数签名

```typescript

  messages: Message[],                              // 原始消息列表
  toolUseContext: ToolUseContext,                 // 执行上下文
  options: {
    maxTokens?: number,                          // 最大保留 token 数
    minTokensToKeep?: number,                     // 最少保留 token 数
    preserveRecentMessagesCount?: number,        // 保留的最近消息数
  }

```

### 1.2 核心流程

```typescript
// src/services/compact/compact.ts:100-150
export async function compactConversation(messages, toolUseContext, options) {
  // Step 1: 剥离图片（节省大量 token）
  const messagesWithoutImages = stripImagesFromMessages(messages)

  // Step 2: 剥离会被重新注入的附件
  const messagesWithoutAttachments = stripReinjectedAttachments(
    messagesWithoutImages,
    toolUseContext
  )

  // Step 3: 尝试会话记忆压缩（优先）
  const sessionMemoryResult = await trySessionMemoryCompaction(
    messagesWithoutAttachments,
    toolUseContext
  )
  if (sessionMemoryResult.success) {
    return sessionMemoryResult
  }

  // Step 4: 回退到 Full Compact（AI 摘要）
  return await performFullCompaction(
    messagesWithoutAttachments,
    toolUseContext,
    options
  )
}
```

**关键设计**：
- **会话记忆压缩优先**：速度更快，不消耗 API
- **Full Compact 兜底**：确保始终能压缩
- 图片剥离是必须的，因为压缩请求本身也可能超出上下文窗口

### 1.3 performFullCompaction 详细流程

```typescript
// src/services/compact/compact.ts:150-250
async function performFullCompaction(messages, toolUseContext, options) {
  // 1. 按 API 轮次分组
  const groups = groupMessagesByApiRound(messages)

  // 2. 分割为 summarize_set 和 keep_set
  //    summarize_set: 需要被压缩的旧消息
  //    keep_set: 保留的近期消息
  const { summarizeSet, keepSet } = splitByCompactionPoint(
    groups,
    options.maxTokens
  )

  // 3. 构建压缩 prompt（getCompactPrompt 只返回指令字符串，不包含待压缩消息）
  const compactPrompt = getCompactPrompt(customInstructions)

  // 4. 调用 fork agent 生成摘要
  const summaryMessage = await runForkedAgent({
    prompt: compactPrompt,
    cacheSafeParams: createCacheSafeParams(toolUseContext),
    canUseTool: createRestrictedCanUseTool(),  // 只允许 FileEdit
  })

  // 5. 创建压缩边界标记
  const boundaryMessage = createCompactBoundaryMessage()

  // 6. 构建压缩后的消息列表
  return buildPostCompactMessages({
    boundary: boundaryMessage,
    summary: summaryMessage,
    keptMessages: keepSet,
    toolUseContext,
  })
}
```

## 2. 消息分组：groupMessagesByApiRound()

**文件**：`src/services/compact/grouping.ts:30-80`

**功能**：将消息按 API 调用轮次分组，用于确定压缩的边界。

### 2.1 分组算法

```typescript
// src/services/compact/grouping.ts:30
export function groupMessagesByApiRound(
  messages: Message[]
): Message[][] {
  const groups: Message[][] = []
  let currentGroup: Message[] = []
  let lastAssistantMessageId: string | null = null

  for (const message of messages) {
    if (message.role === 'assistant') {
      const assistantMsg = message as AssistantMessage

      // 新 assistant 消息 = 新轮次开始
      // 条件：message.id 改变（跨 API 调用）
      if (lastAssistantMessageId !== null &&
          assistantMsg.message.id !== lastAssistantMessageId) {
        groups.push([...currentGroup])
        currentGroup = []
      }

      lastAssistantMessageId = assistantMsg.message.id
    }

    currentGroup.push(message)
  }

  // 最后一组
  if (currentGroup.length > 0) {
    groups.push(currentGroup)
  }

  return groups
}
```

### 2.2 分组示例

```
原始消息序列:
  [user_1] [assistant_1(id=a1)] [tool_result_1] [assistant_2(id=a2)] [tool_result_2] [assistant_3(id=a3)]

分组结果:
  Group 1: [user_1, assistant_1(id=a1), tool_result_1]
  Group 2: [assistant_2(id=a2), tool_result_2]
  Group 3: [assistant_3(id=a3)]

解释：
  - assistant_1 和 assistant_2 有不同的 message.id，说明是两个不同的 API 响应
  - 轮次边界在 assistant 消息 id 变化时划分
```

**设计意图**：
- API 轮次是压缩的最小单位
- 不在轮次中间划分（保持语义完整性）
- 便于计算每个轮次的 token 量

## 3. 图片剥离：stripImagesFromMessages()

**文件**：`src/services/compact/compact.ts:183-210`

**功能**：将图片和文档块替换为文本标记，防止压缩请求超出上下文窗口。

```typescript
// src/services/compact/compact.ts:183
export function stripImagesFromMessages(messages: Message[]): Message[] {
  return messages.map(message => {
    // 只处理有 content 的消息
    if (!message.content) return message

    // 遍历 content blocks
    const newContent = message.content.map(block => {
      if (block.type === 'image') {
        // 图片块 → 替换为 [image] 标记
        return { type: 'text', text: '[image]' }
      }
      if (block.type === 'document') {
        // 文档块 → 替换为 [document] 标记
        return { type: 'text', text: '[document]' }
      }
      // tool_result 中的图片也需要处理
      if (block.type === 'tool_result') {
        const content = block.content?.map(item => {
          if (item.type === 'image') {
            return { type: 'text', text: '[image]' }
          }
          return item
        })
        return { ...block, content }
      }
      return block
    })

    return { ...message, content: newContent }
  })
}
```

**关键点**：
- 递归处理嵌套的 tool_result
- 只替换类型，不改变结构
- 节省的 token 量：一张图片 ~800 tokens

### 4.2 微压缩逻辑

```typescript
// src/services/compact/microCompact.ts:60-100
export function applyMicroCompaction(
  messages: Message[],
  config: TimeBasedMCConfig
): Message[] {
  return messages.map(message => {
    if (message.role !== 'user') return message

    const toolResult = findToolResultInMessage(message)
    if (!toolResult || !COMPACTABLE_TOOLS.has(toolResult.toolName)) {
      return message
    }

    // 检查是否"足够旧"
    const messageAge = Date.now() - message.timestamp
    if (messageAge < config.maxAgeMs) return message

    // 检查消息之后是否有足够的新消息
    const messagesAfter = countMessagesAfter(message, messages)
    if (messagesAfter < config.minMessagesAfterTool) return message

    // 替换为截断标记
    return replaceToolResultWithMarker(
      message,
      `[Old ${toolResult.toolName} result cleared]`
    )
  })
}
```

**适用场景**：
- 用户读取了大量文件后问了一个新问题
- 旧的文件内容不再有用，可以清理

## 5. 会话记忆压缩：Session Memory Compact

**文件**：`src/services/compact/sessionMemoryCompact.ts:80-150`

**功能**：使用会话记忆文件替代完整历史，实现更高效的压缩。

```typescript
// src/services/compact/sessionMemoryCompact.ts:80-120
export async function trySessionMemoryCompaction(
  messages: Message[],
  toolUseContext: ToolUseContext
): Promise<CompactResult | null> {
  // 1. 等待会话记忆提取完成
  const extractionStatus = await waitForSessionMemoryExtraction()
  if (!extractionStatus.success) return null

  // 2. 获取会话记忆内容
  const memoryContent = await getSessionMemoryContent()
  if (!memoryContent) return null

  // 3. 计算保留哪些消息
  const { keptMessages, removedCount } = truncateMessagesForTokenBudget(
    messages,
    memoryContent,
    { minTokens: 10_000, maxTokens: 40_000 }
  )

  // 4. 构建压缩结果
  return {
    success: true,
    messages: [
      createCompactBoundaryMessage(),
      createMemoryReferenceMessage(memoryContent),
      ...keptMessages,
    ],
    stats: { removedMessages: removedCount, strategy: 'session_memory' }
  }
}
```

**优势**：
- 不调用 AI，速度快（~100ms vs ~5s）
- 记忆文件是可读的 markdown
- 可以跨会话持久化

## 练习

### 练习 1：分析压缩触发条件

**问题**：什么情况下会触发 Full Compact？什么情况下会使用 Session Memory Compact？

**答案**：

- **Session Memory Compact**：优先使用，速度快(~100ms)，不消耗 API。当会话记忆提取成功且记忆文件内容在 token 预算内时使用。

- **Full Compact**：Session Memory 失败时的兜底方案，调用 fork agent 生成 AI 摘要。

```typescript
// 压缩决策流程
const sessionResult = await trySessionMemoryCompaction(messages, context)
if (sessionResult.success) {
  return sessionResult  // 快速路径
}
return await performFullCompaction(messages, context, options)  // 兜底
```

**Java 对比**：类似于 Hibernate 一级缓存 → 二级缓存的降级策略。

---

### 练习 2：计算图片剥离节省的 Token

**问题**：如果对话中有 10 张图片，每张图片约 800 tokens，剥离后能节省多少 token？

**答案**：

- 每张图片：800 tokens
- 10 张图片：800 × 10 = **8,000 tokens**

剥离后图片替换为 `[image]` 标记，每个标记只有约 6 tokens。

**计算**：
```
原始：10 × 800 = 8,000 tokens
剥离后：10 × 6 = 60 tokens
节省：7,940 tokens（约 99.25%）
```

---

### 练习 3：追踪消息分组边界

**问题**：给定消息序列 `[user_1] [assistant_1(id=a)] [tool_1] [assistant_2(id=b)] [tool_2] [assistant_3(id=b)]`，如何分组？

**答案**：

按 `assistant.message.id` 变化划分：
- `assistant_1(id=a)` → id 变化（null→a），新组开始
- `assistant_2(id=b)` → id 变化（a→b），新组开始
- `assistant_3(id=b)` → id 不变（b→b），同组

**分组结果**：
```
Group 1: [user_1, assistant_1(id=a), tool_1]
Group 2: [assistant_2(id=b), tool_2]
Group 3: [assistant_3(id=b)]
```

**关键**：相同 id 的连续 assistant 消息会被分到同一组。

### 练习 4：理解微压缩条件

**问题**：MicroCompact 替换工具结果需要满足哪些条件？

**答案**：

必须同时满足：
1. 工具类型在 `COMPACTABLE_TOOLS` 中（FileRead, Bash, Grep, Glob, WebSearch 等）
2. 消息年龄 > `maxAgeMs`（足够旧）
3. 消息之后有足够新消息（`minMessagesAfterTool`）

```typescript
// 三个条件必须同时满足
const messageAge = Date.now() - message.timestamp
if (messageAge < config.maxAgeMs) return message  // 条件2
if (messagesAfter < config.minMessagesAfterTool) return message  // 条件3
if (!COMPACTABLE_TOOLS.has(toolResult.toolName)) return message  // 条件1
```

### 练习 5：压缩边界标记的作用

**问题**：`createCompactBoundaryMessage()` 创建的边界标记有什么作用？

**答案**：

1. **语义标记**：告知后续处理"之前的内容已被压缩"
2. **系统提示**：告诉 AI 不要引用压缩前的消息
3. **处理边界**：系统只处理边界之后的消息

```typescript
// 边界标记结构
{
  type: 'system',
  role: 'system',
  content: [{ type: 'text', text: '[Previous conversation has been summarized]' }],
  isMeta: true,
  compactBoundary: true  // 关键标记
}
```

**Java 对比**：类似于数据库的"墓碑"标记，表示逻辑删除但不立即物理删除。
