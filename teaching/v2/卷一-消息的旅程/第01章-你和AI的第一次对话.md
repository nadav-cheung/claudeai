# 第01章：你和AI的第一次对话

你刚刚在终端里输入了一行字。这行字即将展开一段旅程。

---

## 一个住在你终端里的助手

你用过各种 AI 聊天工具。打开浏览器，访问一个网站，在对话框里打字，AI 回复你。这很好用，但总有点隔阂——像是在跟一个只能通过信件交流的朋友说话。你没法让它帮你改代码、读文件、运行命令。

Claude Code 不一样。它是一个**住在你终端里的 AI 助手**。

想象一下，如果你的电脑前坐着一个真正的人，他能看到你的屏幕、能打开文件、能在终端里敲命令、能帮你写代码也能帮你改 bug。他不需要你把东西复制粘贴给他看，因为他就在你的电脑里，可以直接操作。

Claude Code 就是这个"人"。

当然，它不是一个真的人。它是一个程序——一个运行在你终端里的程序。但它的能力边界很有意思：它能读你的文件、编辑你的代码、执行 shell 命令、搜索你的项目目录。你告诉它你想做什么，它会自己判断需要读哪些文件、运行什么命令、修改哪些代码。

这不是魔法。这是工程。而这本书，就是要把这个工程拆开来给你看。

---

## 第一次运行

我们先别急着拆。先把它跑起来。

**第一步：安装。** 如果你已经装了 Node.js（或者 Bun），一行命令就够了：

```bash
npm install -g @anthropic-ai/claude-code
```

**第二步：进入你的项目目录，启动它。**

```bash
cd your-project
claude
```

然后你的终端变了。光标在闪烁，等待你说话。整个终端变成了一块对话区域——不再是传统的命令行提示符，而是一个可以跟 AI 对话的界面。

**第三步：说点什么。** 比如这一句：

```
帮我修个 bug
```

你按下回车。终端安静了一小会儿，然后文字开始一行一行地出现。它可能先问你："什么 bug？能描述一下吗？"也可能主动开始翻你的代码，看看有什么问题。

几秒之后，它给了你一个回答。也许还帮你改了一行代码。

你看到了输入，你看到了输出。中间发生了什么？

---

## 中间的零点几秒

你按下了回车。"帮我修个 bug" 这几个字——或者说，这几个字节——离开了你的键盘，进入了 Claude Code 的世界。

然后呢？

这是一段极其短暂的旅程，但旅程的每一步都经过了精心设计。你的消息不是直接被丢给 AI 模型的。在被发送出去之前，它要经过几道工序：

- **你的消息会被打包。** 不只是你刚说的这句话，还有之前你们聊过的所有内容，加上一些系统级的"备忘录"——比如你现在在哪个目录下、项目里有哪些文件、AI 被允许做什么。所有这些被组装成一个大包裹。

- **这个包裹会飞向远方。** 通过互联网，到达 Anthropic 的服务器。你的文字在那里被一个大型语言模型处理——这个模型就是 Claude。

- **回答会一个字一个字地飞回来。** 不是等全部生成完了再显示给你，而是像一个正在思考的人，想到一个字就写下一个字。你在终端里看到的文字逐行出现，就是因为这个。

- **有时候，AI 会说"等一下，我要做件事"。** 它可能想读一个文件，或者运行一条命令。这时候 Claude Code 会暂停回复，先执行 AI 要求的操作，把结果再送回给 AI，然后 AI 才继续回答你。

整个过程可能只有几秒钟。但在这几秒钟里，你的消息穿越了终端界面、消息组装管线、网络请求、AI 推理、工具执行、权限检查、结果返回……一路走完了一个完整的系统。

这本书就是跟着这条消息走的。

---

## 为什么要读源码

你可能会问：我为什么要知道这些？我用得好好的，不需要知道里面怎么运作的。

这就像开车。

大多数人开车，不需要知道发动机怎么工作。踩油门走，踩刹车停，方向盘拐弯。这就够了。但如果你是一个赛车手，或者你想要自己改装车，或者你的车出了点小毛病你不想每次都去修理厂——那你就需要知道引擎盖下面是什么。

更重要的是：**知道引擎怎么工作，会让你成为一个更好的驾驶员。**

- 你会知道什么时候该踩油门、什么时候该收着点
- 你会听出引擎声音里的异常
- 你会理解为什么上坡的时候车会变慢
- 你会在出问题的时候有排查的方向

源码就是程序的引擎盖。打开它，你看到的不是魔法，而是齿轮、皮带和气缸——每一样东西都有它存在的理由，每一样东西都跟其他东西咬合在一起。

**读源码能让你成为更好的开发者。** 不只是更好地使用 Claude Code 这个工具，而是理解一个真实的大型项目是怎么被设计、怎么被构建的。这种理解，能迁移到任何项目上。

---

## 什么是"源码"

如果你已经写过代码，可以跳过这一节。

如果你还没写过代码，或者对这个概念有点模糊，让我用一个比喻来解释。

想象你要盖一栋房子。你不会直接拿起砖头就开始砌——你会先画一张蓝图。蓝图上画着每个房间多大、门开在哪里、水管怎么走、电线怎么布。施工队看着这张蓝图，把房子盖出来。

**源码就是程序的蓝图。**

你平时用的每一个软件——浏览器、微信、游戏、还有 Claude Code——都有一份"蓝图"。这份蓝图是用人类能读懂的语言写的（只不过是人类中叫"程序员"的那种人能读懂的语言）。计算机看着这份蓝图，把软件"盖"出来。

你可能会问：那计算机不是只懂 0 和 1 吗？

没错。计算机确实只懂 0 和 1。但在 0 和 1 和人类语言之间，有一层翻译。程序员用人类能读懂的语言写蓝图（源码），然后一个叫"编译器"或"解释器"的程序，把蓝图翻译成计算机能执行的指令。

Claude Code 的源码是用一种叫 TypeScript 的语言写的。TypeScript 是 JavaScript 的一个增强版——如果你听说过 JavaScript，TypeScript 跟它很像，只是多了类型检查。如果你没听说过，也没关系，这本书在需要的时候会解释。

关键是：**源码是可以被人类阅读和理解的。** 它不是黑盒子。只要你愿意花时间，你就能读懂它。

## 这本书怎么读

这是一本不一样的技术书。

大多数技术书按模块组织。先讲模块 A，再讲模块 B，然后讲模块 C。像一本字典——你翻到某一章，学那个模块。这很好，但有个问题：你看不到模块之间是怎么连起来的。

这本书不一样。我们**跟着一条消息走**。

还记得你刚才输入的那句"帮我修个 bug"吗？从你按下回车的那一刻起，这几个字就开始了它的旅程。它会穿过终端界面，被组装成请求，飞过网络，被 AI 处理，可能触发工具调用，最终变成一个回答出现在你眼前。

我们不会先讲"终端模块"再讲"网络模块"再讲"AI 模块"。我们会**跟着你的消息一路走过去**，走到哪儿讲哪儿。走到终端的时候讲终端，走到网络的时候讲网络，走到工具系统的时候讲工具系统。

你会在需要的时候学到需要的东西。而不是先学一堆零件，最后才看到它们怎么组装在一起。

这跟一本叫《网络是怎么连接的》的日本技术书用的是同一种写法。那本书里，作者跟着一个 HTTP 请求，从浏览器出发，一路穿过协议栈、网卡、网线、路由器、交换机，最终到达服务器。读者不需要先学会所有的网络协议，而是跟着请求走，走哪儿学哪儿。

我们做的是同样的事，只不过我们的"主角"不是 HTTP 请求，而是你输入的那行字。

**你不需要按顺序读。** 但我建议你第一遍按顺序来，因为后面的章节会假定你知道前面讲过的东西。如果你已经对某个话题很熟悉了，可以跳着读。

**你不需要会 TypeScript。** 我们会在需要的时候解释 TypeScript 的语法。你只需要会用终端、写过代码（什么语言都行）就够了。

**你不需要事先了解 Claude Code 的架构。** 这本书会带你一步步发现它。

---

## 旅程的地图

在正式出发之前，让我给你一张简略的地图，让你知道我们大概会经过哪些地方：

**卷一：消息的旅程**（你正在读的这卷）

你的消息从终端出发，被组装、被发送、被 AI 处理、可能触发工具调用、最终返回结果。这是最核心的一条线。走完这卷，你就能完整追踪一次请求从头到尾的旅程。

**卷二：引擎室的秘密**

走完主线之后，我们会深入每个"站点"的内部。工具系统是怎么设计的？权限检查的逻辑是什么？上下文是怎么管理的？这卷是给想深入理解设计的人准备的。

**卷三：造物主的工坊**

如果你不只是想理解，还想参与——想给 Claude Code 写代码、提 PR、甚至自己造一个类似的工具——这卷会教你怎么办。

**卷四：架构师的棋盘**

最后一卷，我们站在高处俯瞰整个系统。为什么这里用这种设计？如果换一种方式会怎样？哪些地方是历史包袱，哪些是深思熟虑的结果？

但这些都是以后的事。现在，让我们先从第一步开始。
