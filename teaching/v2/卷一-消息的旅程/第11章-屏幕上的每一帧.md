# 第11章：屏幕上的每一帧

你的终端上出现了 AI 的回答、工具调用的动画、权限确认的对话框。这些东西是怎么被画在终端上的？

回到上一章：AI 完成了新一轮对话，消息数组又多了一条。但不管消息数组里存了多少内容，如果你的终端屏幕没有更新，这一切对你来说就等于没发生。

消息在系统内部流转了这么久，但你还什么都看不到。你的屏幕上发生了什么？

---

## 终端不只是黑白文字

你可能觉得终端就是一个黑底白字的窗口，只能显示纯文本。这想法没错——但也只对了一半。

打开终端，运行 `ls --color=auto`。你会看到文件名是彩色的：目录是蓝色，可执行文件是绿色。运行 `git status`，分支名可能是红色的。运行 `htop`，你看到的是一个不断刷新的、带颜色和进度条的界面。运行 `vim`，你看到的是一个完整的文本编辑器，有状态栏、有语法高亮、有光标移动。

终端早就不是只能显示纯文本了。它支持颜色（前景色和背景色）、粗体、斜体、下划线、光标定位、清屏。这一切都通过一种叫做 **ANSI 转义序列**（ANSI escape sequences）的机制实现——你的程序向终端发送特殊的字符组合，终端收到后不把它们显示为文字，而是解释为"把下面的文字变成红色"或"把光标移到第 3 行第 10 列"。

所以，理论上你完全可以在终端里画出一个精美的界面。问题是，手动管理这些转义序列太痛苦了。想象一下，要画一个两列布局，左边是消息列表，右边是详情面板，你需要自己计算每一行每个字符的精确位置，然后在数据更新时擦掉旧内容、画上新内容。

这就像在一张白纸上用铅笔画画——你能做到，但每画一笔都要精心计算位置，画错了还得擦掉重来。如果有一种方式能让你只描述"我想要什么"，然后有人帮你把画落实到纸上，那该多好。

Claude Code 选了这个"有人帮你画"的方案。这个"人"叫 React。

---

## React：一个"画 UI"的框架

你可能听说过 React。它是目前最流行的前端框架之一，用来构建用户界面。大多数时候，React 被用来构建网页——你在浏览器里看到的 Gmail、Facebook、Instagram 网页版，它们的界面都是用 React 画的。

React 的核心思想非常简单：**你描述你想要的界面长什么样，React 负责把它画出来。**

用生活的例子来说：React 就像一个画师。你不需要告诉画师"先画一条线、再涂一块颜色、再画一条线"。你只需要说"画一个女孩，穿着蓝色的裙子，站在海边"。画师自己会决定用什么笔触、什么颜色、先画什么后画什么。

在 React 里，你描述界面的方式是写 **JSX**——一种看起来像 HTML 的语法。比如，你想在屏幕上显示一段带颜色的文字，你可以这样写：

```jsx
<Box>
  <Text color="green">你好</Text>
</Box>
```

这段代码描述了一个界面：一个方框（`Box`）里面有一段绿色的文字（`Text`）。注意，这不是 HTML——这是 JSX，一种在 JavaScript/TypeScript 代码里嵌入 UI 描述的语法。你写的是代码，但它描述的是界面。

JSX 看起来奇怪吗？想象一下你是一家餐厅的厨师。你可以用自然语言写一份菜单："一盘意大利面，上面撒点帕尔马干酪，旁边放一片罗勒叶"。你也可以用代码写一份菜单：`<Pasta><Cheese type="parmesan" /><Herb type="basil" /></Pasta>`。后者更精确，而且可以被程序处理。JSX 就是后者的思路——用代码精确描述界面。

Claude Code 的源码里到处都是 JSX。但这里有一个问题：React 通常用来画网页，而 Claude Code 是一个终端程序。React 怎么能在终端里画画？

答案是一个叫 **Ink** 的库。

---

## Ink：终端里的 React

Ink 是一个用 React 画终端界面的库。它的口号是"React for CLIs"（命令行界面版的 React）。

正常情况下，React 画网页时，会把你的 JSX 转换成浏览器能理解的 DOM 节点——`<div>` 变成真正的 HTML div 元素，`<span>` 变成 span 元素。浏览器再把这些元素渲染到屏幕上。

Ink 做的事情类似，但目标不同：它把你的 JSX 转换成终端能理解的输出。`<Box>` 变成一个终端里的矩形区域，`<Text>` 变成一段终端文字。Ink 负责计算布局、处理颜色、生成 ANSI 转义序列，最终把正确的内容写到你的终端屏幕上。

Claude Code 没有直接使用 Ink 原版，而是在 `src/ink/` 目录下维护了自己的 Ink 适配层。你打开这个目录看看：

```
src/ink/
├── Ansi.tsx
├── reconciler.ts       -- React 的"翻译官"
├── renderer.ts         -- 把组件树画成终端输出
├── render-node-to-output.ts
├── render-to-screen.ts
├── root.ts             -- 创建渲染根节点
├── screen.ts           -- 终端屏幕的缓冲区
├── terminal.ts         -- 终端能力检测
├── output.ts           -- 输出管理
├── layout/             -- 布局引擎
├── components/         -- 基础 UI 组件（Box, Text, Button...）
├── hooks/              -- React hooks
├── events/             -- 事件系统
├── termio/             -- 终端 I/O
├── ...
```

这个目录里有五十多个文件。不用被吓到——它们各自负责一件小事。`reconciler.ts` 是 React 的"翻译官"，把 React 的指令翻译成终端操作。`renderer.ts` 负责把组件树画到终端。`components/` 里是基础组件。`hooks/` 里是 React hook。这个结构就像一家工厂：不同的车间负责不同的工序，最后组装成你看到的终端界面。

Claude Code 还在 `src/ink.ts`（项目根目录的那个）里做了一层封装。看看这个文件的 `render` 函数：

```typescript
// src/ink.ts，第14-23行
function withTheme(node: ReactNode): ReactNode {
  return createElement(ThemeProvider, null, node)
}

export async function render(
  node: ReactNode,
  options?: NodeJS.WriteStream | RenderOptions,
): Promise<Instance> {
  return inkRender(withTheme(node), options)
}
```

`withTheme` 做的事情很简单——在你的组件外面套一层 `ThemeProvider`。这就像给你的画框先刷上一层底色。所有 Claude Code 的 UI 组件都依赖主题系统来决定颜色，`withTheme` 确保它们不用每次都自己挂载这个 Provider。`render` 函数调用 Ink 底层的 `inkRender`，把 React 组件树送到终端上。

## 组件：搭积木一样搭界面

现在你知道了用 React 描述界面、用 Ink 把界面画到终端。但一个完整的程序界面不是用一堆 `<Box>` 和 `<Text>` 堆出来的——那样太乱了。

React 引入了 **组件**（Component）的概念。组件就是一个函数，它接收一些参数，返回一段 UI。你可以把组件想象成乐高积木——每一块积木有特定的形状和功能，你可以把它们组合在一起，搭出复杂的结构。

一个简单的组件：

```jsx
function Greeting({ name }) {
  return <Text>你好，{name}</Text>
}
```

这个组件叫 `Greeting`，它接收一个参数 `name`，返回一段文字。你可以在任何地方使用它：`<Greeting name="小明" />`，屏幕上就会显示"你好，小明"。

这里的 `name` 叫做 **props**（属性）。你可以把 props 理解为函数的参数。函数 `add(a, b)` 接收两个参数 `a` 和 `b`，组件 `Greeting` 接收一个 prop `name`。它们本质上是一回事——外部世界把数据传进来，组件用这些数据决定输出什么。

Claude Code 的界面就是由无数个这样的组件组成的。它们从小到大，一层套一层：

- 最底层是基础组件：`Box`（矩形区域）、`Text`（文字）、`Button`（按钮）
- 中间层是业务组件：消息气泡、工具调用卡片、权限确认对话框
- 最顶层是整个应用：一个包含所有东西的大组件

从大到小，就像一棵倒过来的树。树根是整个应用，树枝是各个功能区域，树叶是最基础的文字和色块。

---

## 当状态变化时，屏幕自动更新

React 最强大的地方在于：**当数据变了，界面会自动更新。**

想象一个画师在画肖像。模特换了个姿势，画师不需要你告诉他"左手从举着变成了放下，请擦掉左手重新画"。画师会自己观察模特的变化，然后调整画作。

React 也是这样。你的组件里有一些数据（叫做 **state**，状态），当这些数据变了，React 会自动重新"画"界面。你不需要手动更新屏幕上的每一个文字和颜色——你只需要更新数据，React 帮你搞定剩下的事。

回到我们的旅程。你的消息经过了一系列处理，最终被存进了某个状态里。当 AI 正在思考时，有一个状态标记"正在思考中"。当 AI 开始回答时，"正在思考中"变成 false，同时一个新的"AI 回答"状态被创建。当工具调用发生时，"工具调用列表"状态里多了一项。

每一次状态变化，React 都会重新"画"界面。Ink 的 `reconciler.ts` 就是那个翻译官——它接收 React 的指令（"创建一个节点"、"更新这个属性"、"删除这个子节点"），把它们转换成对终端的操作。然后 `renderer.ts` 把这些操作落实到屏幕缓冲区，最终通过 ANSI 转义序列输出到你的终端。

所以，你在屏幕上看到的那些动画效果——打字指示器一闪一闪、工具调用展开收起、进度条向前推进——都不是什么魔法。它们只是状态在不停变化，React 不停地重新画界面，Ink 不停地把新的画面送到你的终端。

## 从 App 到 REPL：组件树的全貌

说了这么多原理，让我们看看 Claude Code 实际的组件树长什么样。

最外层是 `App` 组件。打开 `src/components/App.tsx`：

```typescript
// src/components/App.tsx，第8-13行（编译前的源码）
type Props = {
  getFpsMetrics: () => FpsMetrics | undefined;
  stats?: StatsStore;
  initialState: AppState;
  children: React.ReactNode;
};
```

`App` 是一个包裹组件，它接收四个 props：`getFpsMetrics`（获取帧率数据的函数）、`stats`（统计信息）、`initialState`（应用的初始状态）和 `children`（子组件）。

`children` 这个 prop 很有意思。它代表"放在这个组件里面的东西"。就像一个画框——画框本身有边框和玻璃（`App` 提供的上下文），但画框里放什么画（`children`）由使用画框的人决定。

`App` 组件做的事情很简单——提供三层数据包裹：

1. `AppStateProvider`——应用的状态管理。它像一个公告板，所有组件都可以从这里读取和更新状态。
2. `StatsProvider`——统计数据。追踪用了多少 token、调用了几次 API。
3. `FpsMetricsProvider`——帧率监控。确保界面渲染够流畅。

每一层都是"Provider"——提供者。它们不直接画界面，而是提供数据给下面的子组件用。这就像一栋大楼的地基和管线——你看不见它们，但没有它们，上面的楼层就没法运转。

在 `App` 里面，真正的界面组件是 `REPL`（Read-Eval-Print Loop，读取-求值-打印循环）。打开 `src/screens/REPL.tsx`，看看它的 props 类型定义：

```typescript
// src/screens/REPL.tsx，第526-570行
export type Props = {
  commands: Command[];
  debug: boolean;
  initialTools: Tool[];
  initialMessages?: MessageType[];
  pendingHookMessages?: Promise<HookResultMessage[]>;
  initialFileHistorySnapshots?: FileHistorySnapshot[];
  initialContentReplacements?: ContentReplacementRecord[];
  initialAgentName?: string;
  initialAgentColor?: AgentColorName;
  mcpClients?: MCPServerConnection[];
  systemPrompt?: string;
  appendSystemPrompt?: string;
  onBeforeQuery?: (input: string, newMessages: MessageType[]) => Promise<boolean>;
  onTurnComplete?: (messages: MessageType[]) => void | Promise<void>;
  disabled?: boolean;
  // ... 还有更多
};
```

看到了吗？这个组件接收很多 props。`commands` 是可用的命令列表，`initialMessages` 是初始消息，`systemPrompt` 是系统提示词，`onBeforeQuery` 是发送消息前的回调，`onTurnComplete` 是一轮对话完成后的回调……每一个 prop 都是一条信息通道，把外部世界的数据传入 REPL 组件。

`REPL` 是 Claude Code 界面的核心。它就是你在终端里看到的那个交互界面——底部是输入框，上面是消息列表，中间穿插着工具调用卡片和权限确认对话框。

`REPL` 组件的返回值在最底部（第 5000 行附近）：

```jsx
return <AlternateScreen mouseTracking={isMouseTrackingEnabled()}>
  {/* ... 所有子组件 ... */}
</AlternateScreen>
```

`AlternateScreen` 是一个 Ink 组件，它告诉终端"进入备用屏幕模式"——就像 vim 或 less 做的那样，把终端切换到一个独立的全屏视图。当 Claude Code 退出时，终端会恢复到之前的状态，就像什么都没发生过。

在 `AlternateScreen` 里面，有输入框、消息列表、工具调用展示、权限对话框……所有你看到的东西，都是由更小的组件组成的。消息列表里的每一条消息是一个组件，工具调用展示里的每一个步骤是一个组件，权限对话框里的"允许/拒绝"按钮也是一个组件。

从 `App` 到 `REPL`，再到每一个具体的消息和按钮，整个界面就是一棵巨大的组件树。树根是 `App`，树干是 `REPL`，树枝和树叶是成百上千个更小的组件。每个组件各司其职，只关心自己负责的那一小块界面。

## 一帧的诞生

让我们把本章学到的所有知识串起来，看一次完整的渲染是怎么发生的。

你输入了"帮我修个 bug"。消息经过处理，被添加到了消息数组里。这个动作更新了 React 的状态。接下来：

**第一步：状态变化通知 React。** React 发现状态变了，开始从组件树的根部重新遍历。它问 `App`："你的输出变了吗？" `App` 说"变了"。它问 `REPL`："你的输出变了吗？" `REPL` 说"变了"。它继续往下问，直到找到所有受影响的组件。

**第二步：React 生成新的组件树。** React 对比新旧两棵树的差异——哪些节点新增了，哪些删除了，哪些属性变了。这个过程叫做 **reconciliation**（协调）。Ink 的 `reconciler.ts` 就负责这个过程。它是一个适配器，让 React 的标准协调流程能在终端环境下工作。

**第三步：计算布局。** 组件树有了，但每个组件应该在屏幕的什么位置？多宽？多高？Ink 使用一个叫 Yoga 的布局引擎来计算这些。Yoga 和浏览器的 CSS 布局引擎（Flexbox）使用同一套规则——你写 `flexDirection="column"`，Yoga 就把子元素竖着排列。计算完布局后，每个节点都有了精确的位置和尺寸。

**第四步：绘制到屏幕缓冲区。** `renderer.ts` 遍历布局好的组件树，把每个节点"画"到一块内存缓冲区上。这段代码在 `render-node-to-output.ts` 里——它逐行逐列地把字符写进一个二维数组，同时处理颜色、边框、对齐等样式。

**第五步：输出到终端。** 最后，Ink 把缓冲区和上一帧的缓冲区做对比，找出差异部分，生成最小化的 ANSI 转义序列，发送到你的终端。只更新变化的部分——如果只有一行文字变了，就只更新那一行。这就是为什么你看到界面更新很流畅，而不是整屏闪烁。

整个过程在一帧内完成，通常只需要几毫秒。你的终端每秒可以刷新几十次，而你看到的只是一个流畅更新的界面，感觉就像在和一个真正的人对话。

## 回到那条消息

让我们把视角拉回来。

十个章节之前，你输入了"帮我修个 bug"。这条消息被包装成用户消息，穿越了消息处理流水线，飞过了网络到达 AI，AI 回复了一条消息，决定执行工具调用，工具被真正执行了，结果回到 AI 手中，AI 又想了想，对话越来越长被自动压缩……

而所有这些过程，在系统内部悄悄发生的同时，React 一直在忠实地把每一个状态变化画到你的终端上。AI 开始思考时，你看到一个旋转的加载指示器——那是一个组件，它的状态从"停止"变成了"旋转"。工具调用发生时，你看到一个展开的卡片，显示命令内容和执行结果——那也是一个组件，它的状态从"空"变成了"有内容"。权限确认弹出时，你看到一个对话框，问你是否允许——那还是一个组件，它的状态被设置为"等待用户输入"。

你在屏幕上看到的每一帧，都是 React 根据那一刻的数据状态画出的快照。数据变了，画面就变了。就这么简单。

---

现在你知道一条消息从头到尾经历了什么。从你的键盘输入，到消息的包装和发送，到网络请求和 AI 的响应，到工具调用的执行和结果的返回，到对话历史的压缩管理，再到最终画在你屏幕上的每一个像素——不对，终端没有像素——画在你屏幕上的每一个字符。

是时候打开源码，亲手追踪一次了。
