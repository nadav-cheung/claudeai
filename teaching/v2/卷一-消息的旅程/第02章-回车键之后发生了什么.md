# 第02章：回车键之后发生了什么

你的手指按下了回车键。在屏幕上，这只是换了一行。但在程序内部，一场接力赛刚刚开始。

---

## 终端听到了你的声音

你输入的那行字——"帮我修个 bug"——在按下回车键之前，只是终端里的一串闪烁的光标和文字。终端是一个程序，它的工作就是听你说话：你敲一个键，它显示一个字；你按退格，它删掉一个字。你的输入和终端之间，是一条直接的、即时的连线。

当你按下回车键的那一刻，终端做了一件事：它把你打的那行字**交了出去**。

交给谁？交给正在终端里运行的那个程序——Claude Code。

这个"交出去"的动作，在操作系统的层面，是一次数据的传递。终端把"帮我修个 bug"这几个字打包成一个文本片段，通过一个叫做"标准输入"（stdin）的通道，送到了 Claude Code 正在监听的那个入口。

你可以把标准输入想象成一条传送带。你的终端是一个工人，它把写好的纸条放到传送带上。另一头，Claude Code 正站在传送带旁边，等着接纸条。

但 Claude Code 不是自己站在传送带旁边的。它把这个工作交给了一个专门的组件。

---

## 程序的大门：main() 函数

要理解 Claude Code 怎么接住你的消息，我们得先回到这个程序的起点。每个程序都有一个起点——一个**入口函数**。你双击打开一个应用，或者你在终端里输入一条命令，操作系统做的第一件事就是找到这个程序的入口函数，然后从那里开始执行。

Claude Code 的入口函数叫做 `main()`，它住在 `src/main.tsx` 这个文件里。

```typescript
// 文件：src/main.tsx，约第585行
export async function main() {
  profileCheckpoint('main_function_start');

  // 安全设置：防止 Windows 从当前目录执行命令
  process.env.NoDefaultCurrentDirectoryInExePath = '1';

  // 初始化警告处理器
  initializeWarningHandler();

  // ... 更多初始化工作 ...

  await run();
}
```

**什么是函数？** 函数是一个有名字的代码块。想象一份食谱——食谱有名字（比如"番茄炒蛋"），有步骤（打蛋、切番茄、下锅翻炒），有结果（一盘菜）。函数也是这样：它有一个名字（比如 `main`），有一段代码（做具体的事情），可能还会返回一个结果。

`main()` 这个函数就是 Claude Code 的正门。程序启动的时候，操作系统推开门，走进去，从这里开始往下走。

你可能注意到了，`main()` 前面有两个词：`async` 和 `function`。`function` 声明这是一个函数，`async` 是一个修饰词，意思是这个函数里面有一些操作需要"等待"。

**什么是等待？** 有些事情不是立刻就能完成的。点外卖之后，你得等骑手送过来；你不能在等的这段时间里什么都不做，你会继续做别的事，等外卖到了再吃。程序也一样。`async` 就是告诉程序："这个函数里有需要等的操作，在等的时候别傻站着，去做别的事。"

对应的，代码里会有 `await` 这个词，意思是"等这件事做完了再往下走"。就像你跟朋友说"等我拿个外卖"——你会停在那一句话，拿到外卖之后才继续说话。

---

## 初始化：进门前先做好准备工作

`main()` 函数做的第一件事不是立刻去接你的消息。它先做了一系列准备工作——就像你早上到了公司，先开电脑、泡咖啡、查邮件，然后才开始正式工作一样。

让我们看看它都准备了什么：

**安全检查。** 程序做的第一件事是设置一个环境变量，防止在 Windows 上有人利用当前目录的恶意程序冒充系统命令。这就像一进大楼就检查门锁一样，是一种基本的安全习惯。

```typescript
// 文件：src/main.tsx，约第591行
process.env.NoDefaultCurrentDirectoryInExePath = '1';
```

**警告处理器。** 接着它注册了一个"警告处理器"——一个专门负责听程序内部警告的机制。如果程序在运行过程中遇到了什么不对劲的事情，这个处理器会把警告记录下来，而不是让警告淹没在茫茫的输出里。

```typescript
// 文件：src/main.tsx，约第594行
initializeWarningHandler();
```

**识别你是谁。** 程序需要知道自己是怎么被启动的。你是从终端里直接输入 `claude` 命令启动的？还是通过 VS Code 插件启动的？还是通过 API 调用的？不同的启动方式，程序的行为会有所不同。它会检查一系列环境变量来确定自己的身份。

```typescript
// 文件：src/main.tsx，约第818-833行
const clientType = (() => {
  if (isEnvTruthy(process.env.GITHUB_ACTIONS)) return 'github-action';
  if (process.env.CLAUDE_CODE_ENTRYPOINT === 'sdk-ts') return 'sdk-typescript';
  // ... 更多检查 ...
  return 'cli';
})();
```

这段代码中有一个有趣的结构：`(() => { ... })()`。这叫做"立即执行函数"——定义一个函数，然后立刻调用它。为什么要这样做？因为这里只想用一堆 `if` 来决定 `clientType` 的值，但又不想污染外面的作用域。这就像你在厨房里切菜：把菜板拿出来、切完菜、把菜板收回去，而不是让菜板一直占着台面。

**加载配置。** 最后，它提前加载了一些设置信息（`eagerLoadSettings()`），确保后续的每一步都能读到正确的配置。

所有这些准备工作完成之后，`main()` 调用了一个关键的函数：

```typescript
// 文件：src/main.tsx，约第854行
await run();
```

`run()` 是整个程序的指挥中心。它负责解析你输入的命令行参数、根据不同的模式启动不同的流程。在大多数情况下——也就是你在终端里输入 `claude` 然后按回车——它会走到一个关键步骤：启动 REPL。

---

## REPL：你和 AI 轮流说话的桌子

REPL 这个词你可能见过，也可能没见过。它是一个缩写，全称是 **Read-Eval-Print Loop**，翻译过来是"读取-求值-打印-循环"。光看名字挺吓人，但它的意思其实很简单。

想象一张桌子。你坐在桌子的一边，AI 坐在另一边。规则是这样的：

1. **Read（读取）：** 轮到你说话，你说一句。程序把你说的记下来。
2. **Eval（求值）：** 轮到 AI 回应。AI 想一想，决定怎么回答，可能还会做一些操作（比如读文件、运行命令）。
3. **Print（打印）：** AI 把回答展示给你。
4. **Loop（循环）：** 回到第1步，等你说下一句。

这个循环会一直持续，直到你主动退出（按 Ctrl+C 或输入 `/exit`）。

你在终端里使用 Claude Code 的时候，看到的那个一问一答的界面，就是 REPL 在工作。你说"帮我修个 bug"，这是 Read 阶段；AI 思考并调用工具，这是 Eval 阶段；AI 把结果展示给你，这是 Print 阶段；然后光标又出现了，等你输入下一条消息，这是 Loop。

### REPL 的启动

在 `main.tsx` 里，启动 REPL 的最后一步是通过一个叫 `launchRepl` 的函数完成的。这个函数住在另一个文件里——`src/replLauncher.tsx`。

```typescript
// 文件：src/replLauncher.tsx，完整文件（仅22行）
import React from 'react';

export async function launchRepl(
  root: Root,
  appProps: AppWrapperProps,
  replProps: REPLProps,
  renderAndRun: (root: Root, element: React.ReactNode) => Promise<void>
): Promise<void> {
  const { App } = await import('./components/App.js');
  const { REPL } = await import('./screens/REPL.js');

  await renderAndRun(root, <App {...appProps}>
    <REPL {...replProps} />
  </App>);
}
```

这是整个文件。22行代码，做了一件事：把 REPL 组件挂载到屏幕上。

这里面有几个值得注意的东西。

**`import` 的两种写法。** 文件顶部有一行 `import React from 'react'`，这是在文件被加载的时候就引入 React。但在函数内部，你又看到了 `await import('./components/App.js')` 这样的写法。区别是什么？

顶部的那行 `import` 就像是你开工之前就把工具箱搬到了工作台上——不管用不用得上，先放着。函数内部的 `await import` 则像是你需要某件工具的时候才去仓库里拿——用到才取，不浪费空间。

**为什么这里用"用到才取"的方式？** 因为 REPL 是 Claude Code 最核心的界面，但它引用的组件（`App` 和 `REPL`）都很庞大。如果在程序一启动就把它们全部加载到内存里，启动速度会变慢。所以程序采取了一种策略：先做一些轻量的初始化工作，等你确定需要交互界面的时候，再加载这些大组件。这就像搬家——先把必需品搬进来（枕头、牙刷），家具等确定了摆放位置再搬。

**组件嵌套。** 你可能注意到了这种写法：`<App><REPL /></App>`。这是 React 的语法，表示"REPL 组件被包裹在 App 组件里面"。你可以把它理解成俄罗斯套娃——App 是外面那个大娃娃，REPL 是里面那个小娃娃。App 提供一些全局的上下文（比如性能统计、应用状态），REPL 则负责具体的对话界面。

## 你的消息被一个组件接住了

现在让我们走进 REPL 组件内部，看看当你按下回车键的时候，发生了什么。

REPL 组件定义在 `src/screens/REPL.tsx` 里。这个文件很大——几千行代码。但它做的事情可以浓缩成一句话：管理你和 AI 之间的一问一答。

当你启动 Claude Code 并在提示符后面输入"帮我修个 bug"然后按下回车时，REPL 组件里的一个函数被触发了。这个函数叫 `onSubmit`。

```typescript
// 文件：src/screens/REPL.tsx，约第3142行
const onSubmit = useCallback(async (input: string, ...) => {
  // 重新锁定滚动到底部
  repinScroll();

  // 如果 AI 正在工作，先处理即时命令
  // 否则，把你的消息加入对话队列
  // ...

  // 你的消息现在是一个字符串变量 input
  // 它即将被传递给处理函数
}, [...]);
```

**什么是变量？** 变量是程序里用来存放数据的容器。你可以把它想象成一个贴了标签的盒子。这个盒子的标签叫 `input`，里面放的东西是 `"帮我修个 bug"` 这段文字。

在 TypeScript 里，变量有不同的类型。你可以往盒子里放不同种类的东西：一段文字（字符串 string）、一个数字（number）、一个真假值（布尔 boolean）。`input` 这个变量的类型是 `string`——字符串。

**什么是字符串？** 字符串就是一段文字。在代码里，字符串通常被引号包围：`"帮我修个 bug"` 或者 `'帮我修个 bug'`。引号告诉程序："这里面是一段文字，不是命令。" 就像你在一封信里引用别人说的话，会用引号括起来一样。

你的消息——"帮我修个 bug"——现在就是一个字符串，躺在名叫 `input` 的变量里。它从终端的传送带上被拿起来，放进了这个贴着标签的盒子。

---

## 从按下回车到变量：一次完整的交接

让我们把整个过程串起来。

你按下回车键。终端把你的输入通过标准输入通道传递给 Claude Code 进程。此时，REPL 组件正在运行，它内部的输入框组件（prompt input）一直在监听。当它接收到回车信号，它把输入框里的文字取出来，调用 `onSubmit` 函数，把这段文字作为参数传入。

参数？想象你让朋友帮你拿快递。你会说"帮我拿一下那个蓝色的包裹"。这里"蓝色的包裹"就是一个参数——你传递给朋友的额外信息，让他知道具体要拿什么。在代码里，函数也一样：`onSubmit(input, ...)` 意思是"调用 onSubmit 这个函数，同时把 input 里的内容告诉它"。

从你按下回车到你的消息变成一个变量，只经过了不到一毫秒。人类的感知完全无法察觉这段时间。但对程序来说，这已经完成了好几个步骤：终端捕获按键、传递给标准输入、REPL 组件接收、调用处理函数、把文字存入变量。

你的消息现在已经不在终端的输入框里了。它变成了一串存在于程序内存中的字符——一个字符串。

---

## 站在岔路口

在 `onSubmit` 被调用之后，程序做的第一件事不是立刻把你的消息发给 AI。它先做了一个判断：这是一条普通的消息，还是一个命令？

你注意过吗？在 Claude Code 里，你可以输入以 `/` 开头的命令，比如 `/help`、`/clear`、`/exit`。这些命令不会发给 AI，而是由程序自己直接处理。程序会检查你的输入是否以 `/` 开头——如果是，它会识别出命令名称，执行对应的操作，然后跳过 AI 交互的流程。

```typescript
// 文件：src/screens/REPL.tsx，约第3161行
if (!speculationAccept && input.trim().startsWith('/')) {
  // 这是一个命令，不是发给 AI 的消息
  const trimmedInput = expandPastedTextRefs(input, pastedContents).trim();
  const commandName = /* 提取命令名 */;
  // ... 执行命令 ...
}
```

你的消息是"帮我修个 bug"，不以 `/` 开头，所以它不会被当作命令处理。它会继续往下走，进入真正的 AI 交互流程。

但在进入那个流程之前，你的消息还差一步——它需要被装进一个信封。一个裸字符串是不够的，因为程序需要知道很多关于这条消息的额外信息：这是谁说的？什么时候说的？它是用户消息、系统消息、还是工具返回的结果？

你的消息现在是一个字符串，躺在程序的内存里。但它还不是 AI 能理解的格式——它需要被装进一个信封。
