# 第03章：创建你的第一个工具

[上一章](./第02章-第一次修改.md) 你对 GlobTool 做了一次小手术——在 `call()` 里加了一行日志。你已经会打开源码、找到目标位置、做最小化的修改了。

但那终究是在别人的工具上动手。今天，我们要从一张白纸开始，亲手造一个全新的工具。它会出现在 AI 的工具列表里，AI 会主动调用它，你能在终端里看到它跑起来的样子。

听上去很酷？让我们开始。

---

## 目标

创建一个叫 `Timestamp` 的工具。它做的事情极其简单：AI 调用它时，它返回当前的日期时间。没有文件操作，没有网络请求，没有任何复杂逻辑。纯粹的"输入 -> 输出"。

为什么选它？因为它足够简单，不会让你陷入业务细节；但又足够完整，能让你走通创建工具的全部流程——定义 Schema、写 prompt、实现 call、处理权限、注册到工具池。这五步走完，你就掌握了创建任何工具的模板。

---

## 动手

### 第一步：创建工具目录和文件

打开源码，找到 `src/tools/` 目录。你会看到几十个子目录，每个对应一个工具：`BashTool/`、`GlobTool/`、`FileReadTool/`……

我们也要创建一个。在 `src/tools/` 下新建目录 `TimestampTool/`，然后创建两个文件：

```
src/tools/TimestampTool/
  ├── prompt.ts          # 工具的名字和使用说明
  └── TimestampTool.ts   # 工具的主体实现
```

先写 `prompt.ts`。这个文件负责两件事：导出工具的名字常量，导出 AI 看到的那段使用说明。

```typescript
// 文件：src/tools/TimestampTool/prompt.ts

export const TIMESTAMP_TOOL_NAME = 'Timestamp'

export const DESCRIPTION = `
Returns the current date and time in ISO 8601 format.
Use this tool when you need to know the current date or time — for example,
to timestamp a log entry, calculate elapsed time, or reference "now" in a response.
No parameters needed.
`
```

你看，就这么几行。`TIMESTAMP_TOOL_NAME` 是工具的名字——AI 会用这个名字来调用工具。`DESCRIPTION` 是给 AI 看的简短说明，告诉它什么时候该用这个工具。

对照一下 GlobTool 的 prompt.ts（`src/tools/GlobTool/prompt.ts`），你会发现结构一模一样：一个名字常量加一段描述文本。

### 第二步：定义 inputSchema

现在打开 `TimestampTool.ts`。我们要用 `buildTool` 来构建这个工具。回忆一下卷二第04章的内容：`buildTool` 接收一个 `ToolDef` 对象，帮你填上默认值，返回一个完整的 `Tool`。

第一步是定义输入 Schema——告诉系统（和 AI）这个工具接收什么参数。

我们的 Timestamp 工具不需要任何参数，但 Schema 仍然要定义。在 Claude Code 里，Schema 用 Zod 编写：

```typescript
// 文件：src/tools/TimestampTool/TimestampTool.ts

import { z } from 'zod/v4'
import { buildTool, type ToolDef } from '../../Tool.js'
import { lazySchema } from '../../utils/lazySchema.js'
import { DESCRIPTION, TIMESTAMP_TOOL_NAME } from './prompt.js'

const inputSchema = lazySchema(() =>
  z.strictObject({
    format: z
      .enum(['iso', 'unix', 'locale'])
      .optional()
      .describe(
        'Output format: "iso" for ISO 8601, "unix" for Unix timestamp, ' +
        '"locale" for human-readable local time. Defaults to "iso".'
      ),
  }),
)
type InputSchema = ReturnType<typeof inputSchema>
```

逐行拆解：

- `import { z } from 'zod/v4'`——Zod 验证库，卷二第04章讲过它的双重身份：运行时验证 + 编译时类型推导。
- `lazySchema(() => ...)`——延迟求值的包装器。为什么需要它？因为模块加载时，某些 Zod 依赖可能还没准备好。`lazySchema` 把 schema 的创建推迟到第一次被访问时。你可以在 `src/utils/lazySchema.ts` 里看到它的实现——只有三行，一个带缓存的工厂函数。
- `z.strictObject({ ... })`——定义一个严格的对象 Schema。`strictObject` 不允许出现未定义的额外字段。我给了一个可选的 `format` 参数，让你能体验带参数的工具是怎么定义的。如果真想做到极简，`z.strictObject({})` 也可以。
- `type InputSchema = ReturnType<typeof inputSchema>`——从 `lazySchema` 的返回值推导类型，稍后在 `buildTool` 里用到。

### 第三步：定义 outputSchema

接下来定义输出 Schema，描述工具返回什么数据：

```typescript
const outputSchema = lazySchema(() =>
  z.object({
    timestamp: z.string().describe('The formatted timestamp string'),
    format: z.string().describe('The format that was used'),
  }),
)
type OutputSchema = ReturnType<typeof outputSchema>

export type Output = z.infer<OutputSchema>
```

输出有两个字段：`timestamp` 是格式化后的时间字符串，`format` 是实际使用的格式名称。`export type Output` 让其他文件可以引用这个输出类型。

### 第四步：编写 buildTool 主体

现在到了最关键的部分——用 `buildTool` 组装整个工具：

```typescript
export const TimestampTool = buildTool({
  name: TIMESTAMP_TOOL_NAME,
  maxResultSizeChars: 10_000,

  get inputSchema(): InputSchema {
    return inputSchema()
  },
  get outputSchema(): OutputSchema {
    return outputSchema()
  },

  isConcurrencySafe() {
    return true
  },
  isReadOnly() {
    return true
  },

  async description() {
    return DESCRIPTION
  },

  async prompt() {
    return DESCRIPTION
  },

  userFacingName() {
    return 'Timestamp'
  },

  toAutoClassifierInput() {
    return ''
  },

  mapToolResultToToolResultBlockParam(output, toolUseID) {
    return {
      tool_use_id: toolUseID,
      type: 'tool_result',
      content: output.timestamp,
    }
  },

  renderToolUseMessage(input) {
    const format = input.format ?? 'iso'
    return `Getting current time (${format})`
  },

  async call(input) {
    const format = input.format ?? 'iso'

    let timestamp: string
    switch (format) {
      case 'unix':
        timestamp = String(Math.floor(Date.now() / 1000))
        break
      case 'locale':
        timestamp = new Date().toLocaleString()
        break
      case 'iso':
      default:
        timestamp = new Date().toISOString()
        break
    }

    return {
      data: {
        timestamp,
        format,
      },
    }
  },
} satisfies ToolDef<InputSchema, Output>)
```

内容看起来不少，但我们逐一过一遍，你会发现每个部分都不复杂。

**name**——工具的名字。AI 在 API 请求里用这个名字来标识要调用哪个工具。

**maxResultSizeChars**——工具返回结果的最大字符数。超过这个限制，结果会被保存到文件而不是直接传给 AI。10,000 对我们的简单工具绰绰有余。

**inputSchema / outputSchema**——用 getter 包裹 `lazySchema` 调用。这是 Claude Code 工具的标准写法，确保延迟求值正确工作。

**isConcurrencySafe()**——返回 `true`，表示这个工具可以和其他工具同时执行。读时间不会影响任何状态，所以安全。

**isReadOnly()**——返回 `true`，表示这个工具不修改任何文件或状态。

**description()**——返回工具的简短描述，用于 UI 展示。

**prompt()**——返回给 AI 的详细使用说明。这里和 `description()` 返回同样的内容，因为我们的工具很简单。复杂工具的 `prompt()` 会包含详细的使用指南和注意事项（可以参考 `src/tools/GlobTool/prompt.ts`）。

**userFacingName()**——用户在终端里看到的名字。

**toAutoClassifierInput()**——返回空字符串，因为这个工具不涉及安全问题。安全分类器不需要审查它。

**mapToolResultToToolResultBlockParam()**——把工具的输出转换成 API 需要的格式。我们直接把时间字符串作为 content 返回。

**renderToolUseMessage()**——在终端里渲染"工具正在被调用"的状态。返回一行文字即可。

**call()**——核心逻辑。根据用户选择的格式，用不同的方式格式化当前时间。注意返回值的结构：`{ data: { ... } }`，`data` 字段里放实际输出。

最后的 `satisfies ToolDef<InputSchema, Output>` 是 TypeScript 的类型检查——它确保你写的对象满足 `ToolDef` 的类型要求，但不改变对象的推断类型。

### 你没看到什么

你可能会问：`checkPermissions()` 呢？`isEnabled()` 呢？

它们不见了，因为 `buildTool` 提供了默认值。回忆卷二第04章的 `TOOL_DEFAULTS`：

- `checkPermissions` 默认放行——我们的工具不需要额外的权限控制
- `isEnabled` 默认 `true`——我们的工具始终启用
- `isDestructive` 默认 `false`——正确，获取时间不是破坏性操作

这正是 `buildTool` 的价值：简单工具只需要写核心逻辑，安全相关的默认值自动填上。你写的代码越少，出错的可能性也越小。

### 第五步：注册到工具池

工具写好了，但系统还不知道它的存在。最后一步：把它注册到 `src/tools.ts` 中。

打开 `src/tools.ts`，在文件顶部的 import 区域添加一行：

```typescript
// 文件：src/tools.ts，import 区域
import { TimestampTool } from './tools/TimestampTool/TimestampTool.js'
```

然后找到 `getAllBaseTools()` 函数（大约第193行）。这个函数返回所有基础工具的数组。把 `TimestampTool` 加进去：

```typescript
// 文件：src/tools.ts，getAllBaseTools() 函数内部
export function getAllBaseTools(): Tools {
  return [
    AgentTool,
    TaskOutputTool,
    BashTool,
    // ... 其他工具 ...
    TimestampTool,    // <-- 加这一行，位置不限
    // ... 后续工具 ...
  ]
}
```

加在哪里？只要在数组里就行。顺序不影响功能——最终 `assembleToolPool()` 会对工具按名字排序。

完成。现在编译一下项目，确保没有类型错误。

## 遇到问题？

### 编译时报 "Cannot find module" 错误

```
error: Cannot find module '../../Tool.js'
```

检查 import 路径是否正确。Claude Code 使用 `.js` 后缀的 import（TypeScript 的 ESM 约定），但实际文件是 `.ts`。如果你写了 `.ts` 后缀，改成 `.js`。

### 编译时报类型错误

```
error: Type '...' is not assignable to type 'ToolDef<...>'
```

最常见的三个原因：

1. **漏掉了 `satisfies ToolDef`**——没有它，TypeScript 不会帮你检查工具定义是否完整。加上 `satisfies ToolDef<InputSchema, Output>` 再看报什么错。
2. **Schema 不匹配**——`call()` 里用到的字段和 `inputSchema` 定义的不一致。检查 `call(input)` 里解构的字段名是否和 `z.strictObject({ ... })` 里的 key 一模一样。
3. **缺少必需字段**——`buildTool` 要求至少提供 `name`、`inputSchema`、`call()`、`prompt()`、`description()`、`mapToolResultToToolResultBlockParam()`、`renderToolUseMessage()` 和 `maxResultSizeChars`。逐个对照，看是否漏了哪个。

### 工具注册了但 AI 不调用

你注册好了，但对话时 AI 完全不提这个工具。可能的原因：

1. **忘了在 `getAllBaseTools()` 里添加**——检查 `src/tools.ts`，确认 `TimestampTool` 确实在返回数组中。
2. **`isEnabled()` 返回了 `false`**——虽然默认是 `true`，但如果你覆盖了这个方法并返回了 `false`，工具就会被隐藏。检查你的 `buildTool` 定义里有没有误加 `isEnabled: () => false`。
3. **被权限规则过滤了**——`getTools()` 会根据权限上下文过滤工具。如果你全局设置了 deny 规则，工具可能被过滤掉了。这种情况在正常开发环境下不太会遇到。

### AI 调用了但参数不对

如果 AI 传了你不期望的参数，或者缺少必需参数，问题通常出在 `inputSchema` 上：

1. **`.describe()` 不够清晰**——AI 依赖 `.describe()` 里的文字来理解参数含义。描述越清晰，AI 传参越准确。
2. **用 `z.object` 而不是 `z.strictObject`**——`z.object` 默认允许额外字段，AI 可能会"自由发挥"传一些你没预期的参数。`z.strictObject` 会把多余字段拒之门外。

### `lazySchema` 的陷阱

如果你不用 `lazySchema` 直接写：

```typescript
const inputSchema = z.strictObject({ ... })
```

在大多数情况下也能工作。但一旦你的 schema 引用了其他模块的类型（比如另一个工具的输出类型），就可能触发循环依赖。`lazySchema` 是免费的保险——养成习惯，所有工具都用它。

## 验证

现在来验证你的工具是否真的能工作。

### 1. 编译检查

```bash
npx tsc --noEmit
```

如果没有类型错误，恭喜，第一步通过。

### 2. 启动 Claude Code

正常启动 Claude Code CLI，进入交互模式。然后对 AI 说：

```
现在几点了？
```

如果一切正常，你会看到类似这样的输出：

```
● Timestamp(getting current time)
  2026-05-10T14:32:18.456Z
```

AI 识别出需要知道当前时间，调用了你的 Timestamp 工具，拿到了 ISO 格式的时间戳。

### 3. 测试不同格式

试试说：

```
给我当前的 Unix 时间戳
```

你应该看到类似 `1746888738` 的数字。再试：

```
用人类可读的格式告诉我现在几点
```

你应该看到类似 `2026/5/10 14:32:18` 的本地时间格式。

### 4. 检查工具是否出现在列表中

在对话中让 AI 列出它能使用的工具，或者直接查看系统提示词里是否包含 `Timestamp` 的描述。如果 `prompt()` 的返回值被正确包含，AI 就能看到这个工具的使用说明。

## 回顾

这一章，你从零开始创建了一个完整的工具：

1. **目录结构**——每个工具有自己的文件夹，至少包含一个 prompt 文件和一个主实现文件。
2. **inputSchema**——用 Zod 的 `z.strictObject` 定义输入参数，`lazySchema` 延迟创建避免循环依赖。
3. **prompt()**——写给 AI 的使用手册，告诉它什么时候该用这个工具。
4. **call()**——工具的核心逻辑。接收参数，返回 `{ data: ... }` 格式的结果。
5. **buildTool**——帮你填上 `checkPermissions`、`isEnabled`、`isReadOnly` 等默认值，你只需要写核心代码。
6. **注册**——在 `src/tools.ts` 的 import 区域和 `getAllBaseTools()` 数组中各加一行。

你创建的 Timestamp 工具虽然简单，但它覆盖了工具开发的全流程。以后不管你要创建多复杂的工具——操作数据库、调用 API、解析文件——都是在同样的骨架上填充不同的业务逻辑。
